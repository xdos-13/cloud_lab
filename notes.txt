autopilot mode :
	GKE Autopilot mode is a fully managed Kubernetes operation mode where Google Cloud handles the provisioning and management of nodes. In Autopilot:
	You don’t manage node pools directly; you only define workloads.
	Google automatically schedules pods on appropriately sized nodes, scaling and configuring resources behind the scenes.
	Pods that require resources beyond available capacity are automatically rescheduled or blocked until resources are available, reducing manual intervention.
	In your kubectl get pods output, adservice and recommendationservice are in Pending state. This usually means the scheduler cannot find nodes with enough CPU/memory to run them.
	Autopilot hides this problem because it automatically provisions nodes with the required resources for your pods. In Standard mode, you must manually size node pools to fit all pods; in Autopilot, this limitation is abstracted away.
	In short: Autopilot shifts resource management from the user to GKE, so Pending pods due to insufficient node capacity are less likely to occur.

=====================================
ANALYZING THE PROVIDED CONFIGURATION
=====================================

Here’s a structured analysis of your `cartservice.yaml`, explaining the purpose of the main parameters:

---

## **1. Cart Service Deployment (`Deployment`)**

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: cartservice
  labels:
    app: cartservice
```

* **apiVersion/kind** → Defines this as a **Deployment**, a Kubernetes resource for managing a set of replicated pods.
* **metadata.name** → Unique name for the deployment.
* **labels** → Used for selection and service mapping (`app: cartservice`).

---

### **Spec for Deployment**

```yaml
spec:
  selector:
    matchLabels:
      app: cartservice
```

* **selector.matchLabels** → Determines which pods belong to this deployment. Must match pod template labels.

```yaml
  template:
    metadata:
      labels:
        app: cartservice
```

* **template.metadata.labels** → Labels applied to pods; used for the deployment selector and service targeting.

---

### **Pod spec**

```yaml
    spec:
      serviceAccountName: cartservice
      terminationGracePeriodSeconds: 5
```

* **serviceAccountName** → Kubernetes service account used for pod RBAC permissions.
* **terminationGracePeriodSeconds** → Grace period before forcefully killing a pod during shutdown.

```yaml
      securityContext:
        fsGroup: 1000
        runAsGroup: 1000
        runAsNonRoot: true
        runAsUser: 1000
```

* **fsGroup/runAsUser/runAsGroup** → Sets user and group IDs for running the container; enhances security.
* **runAsNonRoot: true** → Ensures the container does not run as root.

---

### **Container definition**

```yaml
      containers:
      - name: server
        image: us-central1-docker.pkg.dev/google-samples/microservices-demo/cartservice:v0.10.4
        ports:
        - containerPort: 7070
```

* **name** → Container identifier.
* **image** → Container image to run.
* **ports.containerPort** → Internal port exposed by container.

```yaml
        env:
        - name: REDIS_ADDR
          value: "redis-cart:6379"
```

* **env** → Environment variable for the container. Points to the Redis instance for cart storage.

---

### **Resource management**

```yaml
        resources:
          requests:
            cpu: 200m
            memory: 64Mi
          limits:
            cpu: 300m
            memory: 128Mi
```

* **requests** → Minimum CPU/memory required to schedule pod. **Used by Kubernetes scheduler**.
* **limits** → Maximum CPU/memory the container can use at runtime.

---

### **Probes**

```yaml
        readinessProbe:
          initialDelaySeconds: 15
          grpc:
            port: 7070
        livenessProbe:
          initialDelaySeconds: 15
          periodSeconds: 10
          grpc:
            port: 7070
```

* **readinessProbe** → Determines if the pod is ready to serve traffic.
* **livenessProbe** → Detects if the pod is alive; restarts if it fails.
* Both improve reliability and traffic routing.

---

## **2. Cart Service Kubernetes Service**

```yaml
apiVersion: v1
kind: Service
metadata:
  name: cartservice
spec:
  type: ClusterIP
  selector:
    app: cartservice
  ports:
  - name: grpc
    port: 7070
    targetPort: 7070
```

* **Service** exposes pods to other services within the cluster.
* **type: ClusterIP** → Only accessible internally within cluster.
* **selector** → Targets pods with `app: cartservice`.
* **ports** → Maps service port to container port.

---

## **3. ServiceAccount**

```yaml
apiVersion: v1
kind: ServiceAccount
metadata:
  name: cartservice
```

* Provides RBAC permissions for pods if needed.
* Ensures pods run with the correct privileges in the cluster.

---

## **4. Redis Cart Deployment**

* Redis is deployed as a separate pod (`redis-cart`) with its own securityContext, ports, and volume.
* **volume: emptyDir** → Temporary storage for Redis, deleted if pod restarts.
* **resources** → Similar to cartservice; ensures scheduling and limits resource usage.
* **readinessProbe & livenessProbe** → Ensures Redis is running before other pods depend on it.

---

## **Summary**

* `requests` → Controls scheduling; `limits` → caps runtime usage.
* **securityContext** → Ensures pods run with least privileges.
* **probes** → Improve reliability and traffic routing.
* **Service** → Exposes deployment internally to other services.
* **ServiceAccount** → Grants RBAC permissions for pods.
